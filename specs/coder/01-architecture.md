# 01 — Architecture & System Overview

## Goal

Provide the owner of a small neighbourhood restaurant with a single platform
where all customer reviews from Google and UberEats are aggregated, drafted
responses are generated by an AI agent, and the owner approves, edits, or
rejects each reply in a human-in-the-loop flow. Approved replies are posted
back to the originating platform.

## Core Services

- **`ingestion`** — periodically polls source adapters (or receives webhooks),
  normalizes records into the unified model, and persists them.
- **`agent`** — consumes newly ingested reviews, constructs a prompt with
  restaurant context, calls the LLM, runs guardrails, stores a draft reply.
- **`api`** — HTTP/JSON service that serves the web UI and receives webhooks.
- **`poster`** — background worker that publishes approved replies back to
  Google / UberEats and handles retries.
- **`notifier`** — sends notifications to the owner when drafts await review.

All services live inside a single Rust Cargo workspace, sharing common crates
for the domain model, storage, and platform adapters. They may run as one
binary (single-process mode for small deployments) or separate binaries behind
a shared PostgreSQL database.

## Data Flow

1. A new review appears on Google or UberEats.
2. The relevant adapter fetches it (poll or webhook).
3. The ingestion service persists a canonical `Review` record.
4. A job is enqueued for the agent.
5. The agent drafts a reply, stores it as a `ReplyDraft` with state `pending_review`.
6. The notifier alerts the owner.
7. The owner approves / edits / rejects via the web UI.
8. On approval, the poster publishes the reply to the originating platform.
9. The round-trip outcome is stored in the audit log.

## Non-Goals (v1)

- Sentiment dashboards / analytics beyond basic counts.
- Support for platforms other than Google and UberEats.
- Multi-tenant SaaS features (this is scoped to a single restaurant).
- Fully autonomous posting without human approval.

## Guiding Principles

- **Human stays in control.** No reply is ever sent without a human click.
- **Boring, reliable Rust.** Prefer well-known crates and synchronous-looking
  async code over clever abstractions.
- **Small blast radius.** A failure in one adapter must not block ingestion
  from the other.
- **Observable by default.** Every external call is traced and logged.
